# ПР2. Локальний inference спеціалізованої моделі

Матеріали до другої практичної роботи. Повний текст завдання, критерії приймання й контрольні запитання — у документі `ПР2.pdf`, виданому до заняття.

## Задача коротко

Веб-застосунок, який приймає зображення й показує знайдені на ньому обʼєкти: для кожного — клас, рамку й упевненість, а також їхню кількість і час виконання. Модель — готова pretrained, inference **локальний**, без звернення до зовнішнього сервісу. Бекенд на FastAPI, робота з моделлю винесена в окремий модуль.

На відміну від ПР1, тут немає ані мережевих таймаутів, ані кодів відповіді: «двигун» працює на вашій машині. Натомість зʼявляються свої питання — коли завантажувати ваги, який брати поріг упевненості й скільки все це триває.

## Що в цій папці

| Файл | Призначення |
|---|---|
| `app/` | Каркас застосунку |
| `requirements.txt` | Залежності роботи |
| `check_env.py` | Перевірка середовища: Python, пакети, ваги моделі |
| `eval/` | Ваш власний набір для оцінювання якості |

```
app/
├─ main.py                веб-рівень: сторінка і JSON-ендпоінт /api/detect
├─ detector.py            модуль inference — заготовки функцій
└─ templates/index.html   сторінка із завантаженням зображення
```

Каркас дає структуру проєкту й робочий веб-рівень, який уже вміє приймати завантажений файл. **Реалізації в ньому немає:** `load_model` і `detect` підіймають `NotImplementedError`, а ендпоінт не обробляє помилок.

## Початок роботи

```bash
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python check_env.py
```

Для macOS і Linux активація середовища — `source .venv/bin/activate`.

**Запустіть `check_env.py` заздалегідь, не на занятті.** Крім пакетів він завантажує ваги моделі `yolov8n` (близько 6 МБ) — це разова операція, але вона потребує мережі й кількох десятків секунд.

Запуск застосунку з папки `pr2`:

```bash
uvicorn app.main:app --reload
```

Далі відкрийте http://127.0.0.1:8000 — форма завантаження вже працює, а сама детекція завершиться помилкою, доки ви не реалізуєте модуль inference.

## Що реалізувати

| Де | Що зробити |
|---|---|
| `app/detector.py` → `load_model` | Завантажити ваги так, щоб це сталося **один раз** за час життя застосунку, а не на кожен запит |
| `app/detector.py` → `detect` | Прогнати зображення через модель, відфільтрувати за порогом упевненості, зміряти час і повернути структурований результат |
| `app/detector.py` → `DetectionError` | Вирішити, чи достатньо одного типу помилки, чи їх треба розрізняти |
| `app/main.py` → `api_detect` | Спроєктувати обробку збоїв: некоректний файл, порожній файл, помилка моделі — і відповідні HTTP-статуси |
| `app/templates/index.html` | Показати знайдені обʼєкти у зрозумілому вигляді замість сирого JSON |

Рішення, які стоять за кожним пунктом, перелічені в розділі 2 практичної роботи — продумайте їх до того, як писати код.

## Оцінювання якості

Окрема частина роботи — зібрати **5–7 зображень із відомим вмістом** і порівняти з ними результат детектора. Як це зробити й що фіксувати — у [`eval/README.md`](eval/README.md). Цей набір знадобиться й далі: у наступних роботах оцінювання стане систематичним.

## Чекліст самоперевірки

- [ ] Використано готову pretrained-модель; inference виконується локально, без зовнішнього API.
- [ ] Результат структурований: клас, координати рамки й confidence для кожного обʼєкта.
- [ ] Реалізовано фільтрацію за порогом упевненості.
- [ ] Час inference вимірюється й показується.
- [ ] Робота з моделлю винесена в окремий модуль; ваги завантажуються один раз.
- [ ] Ендпоінт повертає JSON при успіху й відповідний HTTP-статус при помилці.
- [ ] Оброблено некоректний ввід: не зображення, порожній файл.
- [ ] Зібрано щонайменше 5 прикладів для оцінювання й проаналізовано типи помилок.
- [ ] Ви можете пояснити кожне ухвалене рішення.
