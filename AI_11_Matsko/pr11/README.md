# ПР11. Спостережуваність і контроль ресурсів AI-компонента

Матеріали до одинадцятої практичної роботи. Повний текст завдання, критерії приймання й контрольні запитання — у документі `ПР11.pdf`, виданому до заняття.

## Задача коротко

Помічник оператора «Сузірʼя» з ПР10 працює — і до вас прийшли з питаннями: скільки коштували чернетки минулого тижня, чому вчора о 14:00 було повільно, чому чернетка Петренка тричі впала, чому за одне звернення заплачено пʼять разів, і хто гарантує, що місячний бюджет ключа не буде перевищено. Застосунок ПР10 не відповість на жодне: журнал подій живе в браузері, реєстр — у памʼяті до перезапуску, uvicorn пише лише `POST /api/drafts 202`.

У цій роботі застосунок ПР10 **доповнюється**, а не переписується: **структурований журнал** (JSON lines) з **ідентифікатором запиту**, провайдером, моделлю, **версією prompt**, тривалістю, статусом, видом збою, токенами й **вартістю** кожного звертання; **кеш відповідей** з обходом за кнопкою «Повторити»; **денний ліміт витрат** з попередженням і відмовою; **аналіз журналу** — повільні, невдалі, повторні, витрати, влучання; **порівняння з кешем і без** на одному потоці замовлень.

## Що в цій папці

| Файл | Призначення |
|---|---|
| `app/` | Каркас застосунку: модулі ПР10 як заготовки для заміни своїми + нові модулі ПР11 |
| `samples/requests.json` | Ті самі вісім звернень, що в ПР10 |
| `requirements.txt` | Залежності роботи (ті самі, що в ПР10) |
| `.env.example` | Зразок налаштувань: усе з ПР10 + журнал, ціни, кеш, ліміт |
| `check_env.py` | Перевірка середовища: Python, пакети, `.env`, папки журналу й стану, зразки, чи перенесено модулі ПР10, які модулі ще заготовки, пробний запит зі `stream_options` — чи приходить `usage` у потоці і скільки коштує запит |
| `eval/` | Сценарії перевірки, готовий скрипт прогону замовлень через API, заготовка скрипта аналізу журналу |

├─ limits.py              заготовка з ПР10 → ваш файл; змін не потребує
├─ drafting.py            заготовка з ПР10 → ваш файл + PROMPT_VERSION, metadata
├─ samples.py             читання зразків (готовий)

У кожній заготовці з ПР10 перший абзац докстрінга каже, що в ній додати для ПР11; нижче — заготовка ПР10 без змін. У нових модулях — перелік рішень, які треба ухвалити. **Реалізації в каркасі немає:** функції підіймають `NotImplementedError`.

## Початок роботи

1. **Середовище:**

   ```bash
   python -m venv .venv
   .venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   copy .env.example .env
   ```

   Для macOS і Linux активація середовища — `source .venv/bin/activate`, копіювання — `cp .env.example .env`. Ключ доступу й ваші значення таймаутів перенесіть у `.env` з папки `pr10`.

2. **Модулі з ПР10** — скопіюйте свої `providers/openai_compat.py`, `providers/mock.py`, `gateway.py`, `jobs.py`, `limits.py`, `drafting.py` з `pr10/app/` поверх заготовок у `app/`. Перш ніж замінювати, прочитайте перший абзац докстрінга кожної заготовки — там перелічено, що в цьому модулі додати для ПР11. `providers/base.py` не замінюйте: у ньому три нові поля `Result`; якщо ви змінювали його в ПР10, перенесіть зміни сюди. Обробники помилок із вашого `pr10/app/main.py` перенесіть у `app/main.py`. Сигнатура `jobs.start` тепер приймає `fresh`.

3. **Перевірка:**

   ```bash
   python check_env.py
   ```

   Запустіть заздалегідь. Скрипт покаже, чи перенесено модулі ПР10, чи доступні для запису `logs/` і `state/`, і зробить пробний запит у режимі streaming зі `stream_options={"include_usage": True}`: чи приходить `usage` в потоці (від цього залежить, чи вартість буде розрахунком або оцінкою), які поля в ньому є і скільки коштує пробний запит за цінами з `.env`.

Запуск застосунку з папки `pr11`:

```bash
uvicorn app.main:app --reload
```

Далі відкрийте http://127.0.0.1:8000 — сторінка працює одразу, панель витрат показує, які модулі ще заготовки. Журнал пишеться в `logs/app.jsonl` з першого запиту.

## Що очікує сторінка

Усе з ПР10 — і додатково. `POST /api/drafts` приймає `{"request_id": "d01", "client": "…", "fresh": false}`; «Повторити» надсилає `fresh: true`. У знімку чернетки й події `done` сторінка шукає `cached` (бейдж «з кешу»), `cost` і `cost_estimated` (вартість, «(оцінка)»), `usage.prompt_tokens` і `usage.completion_tokens`. У помилках показує `request_id` з тіла або заголовка `X-Request-ID`. `GET /api/usage` → `{"budget": {...}, "cache": {...}, "pricing": {...}}`: у `budget` сторінка розуміє `day`, `spent`, `limit`, `remaining`, `warning`, `exceeded`, `resets_at`; у `cache` — `hits`, `misses`, `bypassed`, `entries`. Поле `pending` замість цього — «ще не реалізовано». Вид збою `budget` має свій напис.

## Що реалізувати

| Де | Що зробити |
|---|---|
| `app/providers/*.py`, `app/gateway.py`, `app/jobs.py`, `app/limits.py`, `app/drafting.py` | Перенести з ПР10 |
| `app/drafting.py` | `PROMPT_VERSION`; `metadata` для шлюзу, кешу й журналу; що з запиту можна записувати |
| `app/gateway.py` | Записи про кожну спробу й підсумок; кеш до провайдера і після; перевірка бюджету перед платним викликом і облік після; вартість у результаті |
| `app/jobs.py` | Ідентифікатор запиту у фоновому потоці; `fresh`; `cached`/`cost` у чернетці й події `done`; записи про чернетку |
| `app/providers/openai_compat.py` | `usage` у streaming (`stream_options`), кешовані провайдером токени |
| `app/providers/mock.py` | Правдоподібний `usage` |
| `app/costs.py` → `estimate` | Токени → долари; оцінка без `usage`, позначена як оцінка |
| `app/cache.py` → `make_key`, `get`, `put`, `stats` | Ключ, TTL, сховище, обхід, лічильники |
| `app/budget.py` → `check`, `record`, `status` | Перевірка, облік, стан на диску, межа доби, попередження |
| `app/main.py` | Перенести обробники помилок; `request_id` у тілі помилки; відмова через бюджет, якщо перевіряєте тут |
| `eval/analyze.py` → `slow`, `failed`, `repeated`, `spend`, `cache_report` | Розділи звіту за вашими полями |
| `eval/` | Сценарії, прогони без кешу і з кешем, висновки |

Рішення, які стоять за кожним пунктом, перелічені в розділі 2 практичної роботи — продумайте їх до того, як писати код.

## Чекліст самоперевірки

- [ ] `logs/app.jsonl` — один рядок JSON на подію; запис звертання до провайдера містить ідентифікатори запиту й чернетки, клієнта, провайдера, модель, версію prompt, спробу, час до першого фрагмента й разом, статус або вид збою, запасний варіант, токени, вартість, кеш.
- [ ] Кожна відповідь API має заголовок `X-Request-ID`; тіло помилки містить `request_id`; за ним знаходяться всі записи чернетки, включно з фоновими.
- [ ] У журналі немає ключа, тексту звернення, фактів з іменами й номерами, повного prompt — перевірено `grep`.
- [ ] Вартість рахується за `usage` і цінами з `.env`; без `usage` — оцінка з позначкою; оператор бачить вартість чернетки.
- [ ] Ключ кешу охоплює провайдера, модель, версію prompt, повідомлення, параметри генерації; TTL діє; результат з кешу позначений і не списує бюджет; «Повторити» оминає кеш; `CACHE_ENABLED=0` вимикає кеш без змін у коді.
- [ ] Бюджет: попередження на `BUDGET_WARN_AT` видно на сторінці й у журналі; після вичерпання — помилка виду `budget` з часом відновлення, не 500; перезапуск не обнуляє витрат.
- [ ] `eval/analyze.py` показує повільні (медіана, p95, найдовші), невдалі за видом, повторні (ключ кешу, спроби), витрати за день і модель, частку влучань.
- [ ] Один потік `eval/replay.py` прогнано без кешу і з кешем; порівняно звертання, токени, вартість, тривалість.
- [ ] Шлюз викликає `cache`, `budget`, `costs` і `logging`, не знаючи їхньої будови; веб-рівень не знає про ціни й токени; налаштування — з `.env`.
- [ ] Сценарії з `eval/` прогнано, у тому числі на справжньому провайдері з фактичним `usage`; висновки записано.
- [ ] Ключ не потрапив ані в код, ані в репозиторій, ані в журнал.
- [ ] Ви можете пояснити кожне ухвалене рішення.
